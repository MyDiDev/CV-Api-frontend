# Frontend Architecture & UI/UX Flow Documentation

This document provides a comprehensive overview of the `cv-api-client` frontend architecture and UI/UX flows, designed to assist AI agents and developers in understanding the project structure and behavior.

## Tech Stack
- **Framework:** React 19 (via Create React App / `react-scripts`)
- **Language:** TypeScript
- **Routing:** React Router v7 (`react-router-dom`)
- **State Management:** React Context API (Custom `AuthContext`)
- **Styling:** React Bootstrap (`react-bootstrap`) and standard CSS (`index.css`, `App.css`)
- **HTTP Client:** Native `fetch` API

## Folder Structure
```
src/
├── components/       # Reusable UI components (e.g., Navbar, PrivateRoute)
├── context/          # React Context providers (AuthContext)
├── pages/            # View components corresponding to routes
├── services/         # API integration and external communications (api.ts)
├── App.tsx           # Application entry point & route definitions
└── index.tsx         # React DOM rendering
```

## Architecture & State Management

### Authentication State (`src/context/AuthContext.tsx`)
- The application uses JWT for authentication.
- Auth state is globally managed via `AuthContext`.
- The access token is persisted in `localStorage` under the key `cv_api_token`.
- Exposes `token`, `login(token)`, `logout()`, and `isAuthenticated` boolean to components via the `useAuth` hook.

### API Layer (`src/services/api.ts`)
- All backend communication is centralized in `api.ts`.
- The backend URL is hardcoded to `https://cv-api-uleg.onrender.com`.
- Handles two types of authorization:
  1. **JWT Bearer Token**: Used for user session-based routes (e.g., Dashboard).
  2. **API Key (Bearer)**: Used for accessing the core CV API endpoints (e.g., Evaluate CV, Get Documents, Generate Quiz).

## UI/UX Flow & Routing

The application is structured as a Single Page Application (SPA). Routes are defined in `src/App.tsx`.

### Unauthenticated Flow
If a user is not authenticated, they are automatically redirected to `/login` via the `PrivateRoute` wrapper.
- **`/login`**: User enters credentials. On success, the JWT token is saved, and the user is redirected to the dashboard.
- **`/register`**: User creates a new account.

### Authenticated Flow (Protected Routes)
These routes are protected by the `PrivateRoute` component, which verifies the `isAuthenticated` state from `AuthContext`.
- **`/dashboard`**: The main landing page post-login. Fetches and displays statistics/metrics using the JWT access token.
- **`/api-key`**: Users must generate or retrieve an API Key to use the core CV evaluation features. The API requires re-entering the `username` and `password` to retrieve or create the API key.
- **`/documents`**: Displays a list of documents (CV evaluations/quizzes) generated by the user. This endpoint requires the **API Key** for authorization, not the standard JWT token.

## Key Developer Notes for Agents
- **Styling modifications:** Prefer using React Bootstrap components (`Container`, `Row`, `Col`, `Button`, `Form`, etc.) to maintain visual consistency.
- **Adding new routes:** 
  1. Create the page component in `src/pages/`.
  2. Add the route to `src/App.tsx`.
  3. Wrap with `<PrivateRoute>` if it requires authentication.
- **Adding new API calls:**
  1. Add the function to the `api` object in `src/services/api.ts`.
  2. Ensure appropriate error handling (throwing readable errors based on `res.ok`).
  3. Determine whether the endpoint requires the JWT token or the API Key for authorization.
